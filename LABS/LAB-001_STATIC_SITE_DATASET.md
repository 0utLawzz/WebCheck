# LAB 001 — Static Website Baseline Dataset

Status: PLANNED
Phase: A — Draft / Research Lab

## Purpose
Build one deliberately simple five-page static website and use it as the first evidence set for the book.

## Pages
1. Home
2. About
3. Services
4. Portfolio
5. Contact

## Static Baseline
No database, authentication, payments, CMS, custom backend, AI feature, or unnecessary API. The contact form is display-only for this baseline.

## Build Options
Compare ChatGPT, Google AI Studio, and Grok using substantially the same website brief. Record the prompt, tool/model, generated files, framework, routes, dependencies, preview method, deviations, and verification date.

## Evidence Flow
1. Generate the site and capture the prompt/result.
2. Inspect pages, routes, dependencies, metadata, and 404 status.
3. Preview locally or in the builder.
4. Put the baseline project in GitHub.
5. Enable GitHub Pages.
6. Open the published URL and verify the five pages and navigation.

## GitHub Pages Path To Verify
Repository → Settings → Pages → Build and deployment → Source → Deploy from a branch → branch → /(root) → Save.

## Candidate 20–30 Page Chapter
Definition → what static means → build options → exact prompt → inspect generated project → preview → GitHub → GitHub Pages → published URL → first live verification → what is intentionally not tested → transition to the real audit.

## Later Static Audit
Content completeness, links/navigation, mobile, browsers, 404, HTTPS, favicon, titles, meta description, robots.txt, sitemap, image optimization, accessibility basics, performance, social metadata, legal/trust, domain/DNS, and deployment/update workflow.

Important: the baseline website is not supposed to be perfect. The later audit is the point of the book.
