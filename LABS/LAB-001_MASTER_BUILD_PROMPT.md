# LAB 001 — Master Static Website Build Prompt

## Purpose

This is the single controlled build brief for comparing ChatGPT, Google AI Studio, and Grok.

Use the same prompt, with no feature additions, for each tool so the outputs can be compared fairly.

## Master Prompt

Create a simple, professional, responsive static business website for a fictional company called "Northstar Creative Studio".

This website is a controlled learning and testing project for a practical pre-launch website checklist book. The goal is to create a realistic but deliberately simple baseline website that we can inspect, publish, and later test for launch readiness.

### Pages

Create exactly these five main pages:

1. Home
2. About
3. Services
4. Portfolio
5. Contact

A custom 404/not-found page may be included if the chosen framework or build method supports it naturally.

### Business

Northstar Creative Studio is a fictional small business providing:

- Branding
- Website design
- Digital services

Create coherent fictional branding and realistic original sample copy.

Do not use Lorem Ipsum, unfinished placeholder text, "Your text here", or unfinished sections.

Portfolio projects must be clearly fictional/sample projects. Do not present invented testimonials, reviews, clients, awards, statistics, or business results as real facts.

### Design

Create a clean, professional, modern business website.

Requirements:

- Responsive desktop layout
- Responsive tablet layout
- Responsive mobile layout
- Clear navigation
- Consistent visual identity
- Readable typography
- Sensible spacing
- Professional footer
- Footer navigation
- Fictional contact information
- No unnecessary visual complexity

The site should look like a small real business website, not an advanced software demonstration.

### Contact Page

Include a contact form containing:

- Name
- Email
- Message
- Submit button

The form does NOT need a working backend.

Make it clear through the implementation that this is only a front-end/static demonstration if necessary.

### Technical Scope

This must remain a STATIC WEBSITE.

Do NOT add:

- Database
- Authentication
- Login/register
- User accounts
- CMS
- Admin dashboard
- Payment system
- E-commerce
- AI/chatbot feature
- Custom backend
- Server-side application logic
- Unnecessary APIs
- Unnecessary external services
- Analytics unless absolutely required by the chosen tool
- Newsletter system
- Real contact-form processing
- Unnecessary libraries or frameworks

Do not add features simply to make the project appear more sophisticated.

### Metadata

Include basic page metadata such as:

- Meaningful page titles
- Basic meta descriptions where appropriate
- Sensible document structure

Do not perform a full SEO audit. We will test SEO later.

### Images and Assets

Use suitable sample visuals for the fictional business.

If external images are used, identify their source/dependency.

If generated or placeholder visuals are used, make them appropriate to the fictional business.

Do not introduce unnecessary image services or APIs.

### Beginner Readability

Keep the project simple enough that a beginner can inspect it.

Avoid unnecessary abstractions and complicated architecture.

The resulting project should make it reasonably clear:

- Where the pages/routes are
- Where the text/content is
- Where images/assets are
- Where styles are defined
- Where metadata is defined

### Important Scope Rule

Do not try to make this website "launch-audit perfect".

The purpose of this experiment is to create a realistic baseline and then deliberately test it.

Therefore, do not automatically add advanced SEO, accessibility, performance optimization, security hardening, analytics, monitoring, testing systems, or other audit tooling unless required by the basic requirements above.

### Verification Rule

Do not claim that something works unless you actually verified it.

If you cannot verify something, say so.

If a requirement cannot be implemented because of the chosen tool or framework, state the limitation instead of hiding it.

### Final Handoff

After completing the website, stop and provide a concise handoff report.

Do NOT perform the full pre-launch audit yet.

Report:

1. Build status — whether the requirements were completed.
2. Pages/routes created.
3. Features actually implemented.
4. Framework/tool used.
5. Basic project/file structure.
6. Where page content, images, styles, and metadata are located.
7. Testing actually performed and results.
8. Known limitations or deviations.
9. External dependencies, libraries, APIs, fonts, or image sources.
10. What is intentionally NOT included.
11. What should be done next: publish and begin the controlled pre-launch testing process.

Do not add extra features after the handoff.

## End of Master Prompt

## Experiment Protocol

For each AI builder:

- Use this exact prompt.
- Do not manually improve the prompt for one tool.
- Record the tool/model and date.
- Save the exact prompt used.
- Capture the relevant generation/preview screen.
- Record what was actually produced.
- Record deviations and limitations.
- Do not judge which tool is better until all selected outputs have been inspected.

## Comparison Principle

The experiment compares the output and workflow, not marketing claims about the tools.

The same brief should produce evidence that can later be discussed in the book.
